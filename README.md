# 4TH DOWN — Live NFL Decision Grader v0.3

A live, outcome-blind NFL fourth-down decision grader with an **independent nfl4th validation layer**.

## Why v0.3 exists

v0.2.x fixed the ugly data problems first: possession, score state, field side, punt geometry and pre-play state reconstruction. v0.3 moves to the next problem: **is the decision math itself trustworthy?**

The app now separates:

1. **Primary live model** — the fast JavaScript counterfactual engine used during games.
2. **nfl4th benchmark** — exact output from `nfl4th::add_4th_probs()` generated by GitHub Actions for audited games.
3. **Consensus policy** — strong primary/nfl4th disagreements are shown as `MODEL SPLIT • REVIEW` instead of pretending one model is ground truth.

This is deliberately more conservative about certainty.

## New in v0.3

- Adds an exact **nfl4th benchmark workflow** in `.github/workflows/nfl4th-benchmark.yml`.
- Runs `nfl4th::get_4th_plays()` + `nfl4th::add_4th_probs()` in R on GitHub Actions.
- Writes benchmark output to `public/benchmarks/<ESPN_EVENT_ID>.json`.
- The live app fetches the latest benchmark directly from the GitHub repository, so benchmark updates do **not** require another Render deploy.
- The decision ledger shows both:
  - `PRIMARY` GO / FG / PUNT win probabilities
  - `NFL4TH` GO / FG / PUNT win probabilities
- Adds `CONSENSUS WITH NFL4TH`, `MODEL DIFFERENCE • LOW MARGIN`, and `MODEL SPLIT • REVIEW` states.
- Strong model splits suppress the punitive grade and WPA Burn display until reviewed.
- Adds benchmark coverage, exact-call agreement and strong-split counts to the selected-game ledger header.
- Adds a published nfl4th regression check: the 2020 GB–TB 4th-and-8 decision must prefer GO.
- Total automated JavaScript tests: **24**.

## How the benchmark pipeline works

```text
GitHub push / workflow dispatch
          |
          v
GitHub Actions + R
          |
          v
nfl4th::get_4th_plays(game_id)
          |
          v
nfl4th::add_4th_probs()
          |
          v
public/benchmarks/<espn_id>.json
          |
          v
Render app fetches raw benchmark JSON
          |
          v
PRIMARY vs NFL4TH consensus / split
```

## Grading policy

The primary model remains outcome-blind. A failed attempt can still be an A+ decision.

But v0.3 adds a second rule: if the primary model and a **non-fragile nfl4th benchmark** strongly disagree on the optimal call, the UI displays **REVIEW** rather than a C/D/F grade. The goal is to avoid fake authority while the model is still being calibrated.

## Model status

The primary model is still a research prototype. It uses:

- ESPN pre-play win probability as an optional live anchor
- fourth-down conversion probability
- field position
- score and clock
- timeouts
- field-goal probability
- punt field compression
- late-game possession/scoring-class logic
- sensitivity testing

The nfl4th benchmark is independent and richer in several areas, including game context such as betting-market strength and its own trained conversion/WP models. It is used as a **validation reference**, not blindly copied into the live engine.

## Benchmark a game manually

After v0.3 is pushed to GitHub:

1. Open the repository on GitHub.
2. Open **Actions**.
3. Select **nfl4th benchmark**.
4. Click **Run workflow**.
5. Enter an nflverse game ID such as `2026_03_ATL_GB`.

The workflow writes the benchmark JSON back to the repository. The deployed site reads it from GitHub automatically.

If the workflow cannot push its JSON, go to **Settings → Actions → General → Workflow permissions** and allow **Read and write permissions** for the repository workflow token.

## Data integrity protections carried forward

- explicit possession team on every decision
- pre-play score from the offense's perspective
- exact quarter / clock / distance
- field-side reconstruction from explicit spot text
- punt-geometry and FG-distance cross-checks
- no grading when strong state sources cannot be reconciled
- raw play text and field-position source shown in the ledger

## Live provider

The prototype uses ESPN public/undocumented football endpoints for live scoreboard, game summary, play-by-play and win-probability data. The provider is isolated in `lib/espn.js` so it can be replaced later.

## Next step after v0.3

Use the generated Falcons–Packers nfl4th benchmark to identify **where and why** the primary engine disagrees. Then calibrate the primary model by component rather than by vibes:

- conversion model error
- FG make model error
- punt outcome error
- WP state-transition error
- late-game scoring-state error
- team-strength / market-context error

Only after that should season-long coach leaderboards become a serious product feature.
